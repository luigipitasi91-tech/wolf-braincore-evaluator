WOLF BrainCore Evaluator — App Map

This map follows one request from input to evidence receipt. It is a code-navigation aid, not submission prose.

Request→BrainCore planner→WOLF rubric→Finality→SHA-256 receipt

1. Request → two plans

src/braincore.mjs contains buildBaselinePlan() and buildBrainCorePlan(). Both receive the same request. The candidate explicitly separates constraints, assumptions, unknowns, definition of done, plan, and verification.

2. Same rubric → comparable evidence

src/evaluator.mjs contains evaluatePlan(). It scores both plans on the same five dimensions. comparePlans() then applies score, delta, and critical-gap gates.

3. Evidence → finality

comparePlans() returns PROMOTE, HOLD, or REJECT. A candidate cannot promote solely because its text is longer.

4. Finality → receipt

src/app.js serializes the evaluated request and decision, hashes it with browser Web Crypto SHA-256, and renders the receipt. Changing the request changes the evidence payload and hash.

5. What proves it works

tests/planner.test.mjs and tests/evaluator.test.mjs cover constraint extraction, unknowns, scoring, promotion, rejection, hold behavior, and score bounds. Run npm test.

Project-grounded practice to reuse: when changing an agent prompt, skill, or planning architecture, keep the test input and rubric fixed. Compare the old and new behavior before promoting the change.

Try one safe experiment

In src/evaluator.mjs, inspect the promotion thresholds inside comparePlans(). Predict how changing only the delta threshold would affect promotion, then use the tests before accepting any change. The practice is: change one evaluation rule, predict the effect, verify, then decide.
