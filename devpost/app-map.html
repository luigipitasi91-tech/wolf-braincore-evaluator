WOLF BrainCore Evaluator — App Map

Final hardened competition build: minimal entry, independent request integrity, domain evidence packs, deterministic evaluation and verifiable finality.

Wolf + W request→ Request Integrity→ Domain Packs→ Baseline + Candidate→ WOLF rubric→ Critical blockers→ Finality→ SHA-256 receipt

1. Minimal landing

index.html exposes only the WOLF emblem, request bar and W submit action.

2. Independent Request Integrity

src/request-integrity.mjs detects semantic vagueness, contradictions, constraint override and evaluator-gaming before candidate scoring can promote a result.

3. Domain evidence

src/domain-packs.mjs adds finance and browser-agent evidence contracts only when relevant.

4. Same request → two plans

src/braincore.mjs creates baseline and BrainCore candidate from the same request. External structured candidates can instead enter through src/external-candidate.mjs.

5. Same rubric → comparable evidence

src/evaluator.mjs scores ambiguity resolution, assumption exposure, constraint retention, definition of done and verification readiness, then applies integrity blockers.

6. Balanced regression evidence

src/benchmark.mjs runs 8 fixed core cases. src/domain-benchmarks.mjs adds 10 finance and 6 browser-agent transfer cases.

7. Receipt

src/app.js hashes the evaluated evidence payload with Web Crypto SHA-256.

8. What proves it works

The Node test suite covers request integrity, core finality, domain transfer, external candidates and planner invariants. Current target: 25 passing tests.

Reusable practice: hold the request set and rubric fixed, keep request integrity independent from candidate scoring, and promote only when measured evidence improves without critical regressions.
