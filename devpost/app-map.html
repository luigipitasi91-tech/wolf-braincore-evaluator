WOLF BrainCore Evaluator — App Map

Final competition build: minimal W entry point, deterministic evaluation, fixed benchmark, and evidence receipt.

Wolf + W request→ BrainCore planner→ WOLF rubric→ Critical-gap gate→ Finality→ SHA-256 receipt

1. Minimal landing

index.html exposes only the WOLF emblem, request bar, and W submit action. src/app.js transitions from landing to evidence view only after a valid request.

2. Same request → two plans

src/braincore.mjs creates buildBaselinePlan() and buildBrainCorePlan() from the exact same input.

3. Same rubric → comparable evidence

src/evaluator.mjs scores both plans on ambiguity resolution, assumption exposure, constraint retention, definition of done, and verification readiness.

4. Fail-closed guard

Severely under-specified requests receive CRITICAL_INPUT_UNDERSPECIFIED. A high structural score cannot override that critical blocker.

5. Fixed benchmark

src/benchmark.mjs runs four fixed cases through the exact same planner and evaluator. The under-specified case is expected to produce a non-PROMOTE finality.

6. Receipt

src/app.js hashes the evaluated request and decision evidence with browser Web Crypto SHA-256.

7. What proves it works

tests/planner.test.mjs, tests/evaluator.test.mjs, and tests/benchmark.test.mjs protect planner behavior, score/finality rules, and fail-closed benchmark behavior.

Reusable practice: hold the request set and rubric fixed while changing one cognitive component at a time. Promote only when measured evidence improves without critical regressions.
